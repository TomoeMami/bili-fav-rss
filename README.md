# bilibili 收藏夹 → 个人播客 RSS

一个「让 AI Agent 帮你实现」的文档项目：公开版**只包含文档，不含可直接运行的代码**。
把构建规格和推荐 prompt 发给任意编码 Agent（Claude Code / Codex / Cursor / DSH 等），
它会在一个空目录里从零实现一个**只在局域网运行、个人自用**的播客 RSS 服务：

- 读取公开收藏夹，按收藏时间倒序生成 RSS；
- 音频由本地服务中转，播客客户端无需任何特殊设置；
- 浏览器密码登录 + 账号授权 + 带 token 的订阅地址。

> 目标平台 bilibili 仅作描述性提及；本项目**非官方、与 bilibili 无关联**。
> 仅限个人、局域网、非商业使用；平台条款与法律风险由使用者自行承担。

## 怎么用

1. 打开 [`AGENT_SPEC.md`](AGENT_SPEC.md)，**全选复制全文**。
2. 复制下面的「推荐 prompt」。
3. 把 prompt 和规格全文一起发给你的编码 Agent，让它在**空目录**里实现。
4. 按 Agent 的输出运行 `node server/test.mjs`，再用你自己的公开收藏夹做端到端验证。

## 推荐 prompt

```text
你是资深 Node.js 工程师。请在当前空目录中实现我随后粘贴的《Agent 构建规格》所描述的项目。

硬性要求：
1. 先读规格 §0「合规边界」，把它当硬约束，不要扩展范围。
2. 规格没有提供的平台接口细节，由你自行检索、验证；不要猜测、不要硬编码；优先使用官方公开 API。
3. 禁止绕过访问控制、风控、验证码或付费保护。如果无法在不绕过保护的前提下完成，停止并输出阻塞报告。
4. 技术栈：Node >= 20、ESM、零 npm 依赖；服务默认只监听 127.0.0.1 或我指定的局域网 IP，不要监听 0.0.0.0。
5. 不要在任何文件、日志、提交信息里写入真实 Cookie、token、密码或收藏夹数据。
6. 完成后运行 server/test.mjs，输出：测试结果、运行命令、已知限制、合规声明。

以下是我的《Agent 构建规格》全文：
<在这里粘贴 AGENT_SPEC.md>
```

## 推荐发送的文档

| 文档 | 是否发送 | 说明 |
| --- | --- | --- |
| [`AGENT_SPEC.md`](AGENT_SPEC.md) | ✅ 必须，全文 | 目标、架构、自有接口、RSS 契约、验收标准、调研清单 |
| `README.md`（本文件） | ❌ 不需要 | 给人看的说明 |
| 其他本地文件（实现、部署记录、研究笔记） | ❌ 不要 | 不需要发给 Agent，也不建议公开 |

可选补充（附在 prompt 后面）：

- 运行环境（OS、Node 版本）；
- 是否需要 systemd / Docker；
- 是否需要 HTTPS（仅局域网通常不需要）；
- 你的公开收藏夹页面 URL（**不要**贴 Cookie、token 或账号凭据）。

> 如果你的 Agent 无法联网检索：让它先用 mock/fixture 实现全部结构与测试，接口层留出适配点，
> 再由你自己补上真实接口细节。

## 完成后你会得到

- `server/`：零依赖 Node 服务（网页登录、账号绑定、`/rss`、`/audio`）；
- 一个局域网网页：生成带 token 的订阅地址，复制到播客客户端即可；
- `server/test.mjs`：集成测试；
- 运行说明、已知限制与合规声明。

## 重要边界

- 只处理**公开**收藏夹；只使用**你自己的账号**；只播放你账号本来就有权播放的音频。
- 不要公网部署、不要多用户共享、不要镜像/转存/再分发音频。
- Agent 不得绕过平台访问控制、风控或验证码；无法合规完成时应停止并报告。
- 本项目文档**不包含**任何第三方接口地址、参数、签名算法或字段清单。
